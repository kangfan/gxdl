## 二、重构目标与已确认决策

用户确认的方向：

1. 参考 UnityGameFramework 的分层思想：流程（Procedure）、系统（System）、界面模块（Module）。
2. 登录 → 大厅 → 副本 → 战斗 作为流程（Procedure）。
3. 任务、养成等作为 UI 模块，按 MVC 拆分。
4. 每个系统有 System / Data / Controller 三层。
5. UI 基于 UGUI，**改造为 prefab 式**。
6. 角色与技能系统按数据驱动，视图与数据分离。
7. System 全局唯一，但**不用静态单例**，改用组合根注册。
8. 重构与清理全部完成后再统一自测。
9. 首次推送到远程仓库的内容必须是重构且清理后的干净版本。
10. 远程仓库：`https://github.com/kangfan/gxdl.git`（首次交接时为空仓库，0 分支）。

## 四、核心约定（改代码前必读）

### 4.1 服务获取

系统不使用静态单例。全部经 `GameContext` 取用：

```csharp
var saves = GameContext.Get<ISaveSystem>();
if (GameContext.TryGet<IGrowthSystem>(out var growth)) { ... }
```

未注册的服务直接抛 `InvalidOperationException`，不返回 null。
服务在 `GameBootstrap.Initialize()` 中一次性注册，顺序即依赖顺序。

### 4.2 事件

事件定义集中在 `GameEvents`，全部是 `readonly struct`。
订阅必须成对释放，`UiModule.Track<T>()` 会在模块销毁时自动释放：

```csharp
Track<GameEvents.PlayerStatsChanged>(e => RefreshPower(e.Power));
```

事件处理器抛异常不会影响其他订阅者（总线内部已捕获）。

### 4.3 流程切换

流程不自行跳转，一律请求 `ProcedureManager`：

```csharp
procedures.Change(ProcedureIds.Lobby);
```

`CanEnter()` 为假时拒绝切换；在 `OnEnter`/`OnLeave` 内再次请求切换会抛异常（防重入）。

### 4.4 命名空间陷阱

历史遗留类型 `Battle`、`Role` 等位于根命名空间 `Gxdl`。
**不要**把新命名空间命名为 `Gxdl.Systems.Battle` 或 `Gxdl.Systems.Role`，
否则会遮蔽同名类型导致级联编译错误。当前统一使用根命名空间 `Gxdl.Systems`。

## 五、UI prefab 化流程

### 5.1 为什么用代码生成而不是运行时抓取

原界面完全由代码在运行时创建，场景中没有任何 UI 节点。
运行时抓取会把动画的中间状态（位置、缩放、颜色）烘进 prefab。
代码生成写的是静态骨架，初始值确定可控。

### 5.2 四步流程

1. 写生成器：`Assets/Editor/XxxPrefabSource.cs`，用 `UiPrefabBuilder` 描述节点。
2. 写 View：`Assets/Scripts/Modules/XxxView.cs`，继承 `UiModule`，字段用 `[SerializeField]`。
3. 菜单生成：`Gxdl/UI/生成/...`，产出 `Assets/Resources/UI/XxxView.prefab`。
4. `UiViewBinder.Bind()` 自动挂组件并连线字段（生成器里已调用）。

### 5.3 锚点规则（重要）

**禁止**照抄固定像素坐标堆满一整页。按语义分区：

| 用途 | 锚点预设 |
| --- | --- |
| 背景、遮罩、内容区 | `Stretch` |
| 顶栏 | `StretchTop`（宽拉伸、高固定） |
| 底部导航 | `StretchBottom` |
| 居中弹窗、图片槽 | `Center` |
| 角落按钮 | `TopLeft` / `TopRight` / `BottomRight` |
| 贴边文本 | 对应边的中点锚点 |

界面根节点挂 `UiRootLayout`（宽 750、高随屏幕）+ `SafeAreaFitter`（避开刘海与手势条）。
验收时至少切换三种分辨率：750×1334、1080×2400（长屏）、2048×1536（平板）。

### 5.4 已完成

- `StoryOverlayView`：开场动画界面。prefab 已生成，锚点布局生效，7 个镜头共用两个图片槽。

## 七、自测方式

### 7.1 Unity Bridge（unity-tools）

编辑器通过 TCP Bridge 接入，端口写在 `.com-unity-codely.json`，每次 Unity 重启可能变化。
外部调用走 `.agents/skills/unity-tools/scripts/unity_bridge_cli.py`：

```bash
python .agents/skills/unity-tools/scripts/unity_bridge_cli.py state
python .agents/skills/unity-tools/scripts/unity_bridge_cli.py call unity_editor '{"action":"request_compile"}'
python .agents/skills/unity-tools/scripts/unity_bridge_cli.py exec-file path/to/probe.cs
```

注意事项：

- 系统 PATH 里的 `python` 是 WindowsApps 存根，需用实机解释器
  （当前为 `C:\Users\admin\AppData\Local\Python\bin\python.exe`）。
- 含中文的参数不要直接写在命令行里，会被 shell 编码破坏；改用 JSON 文件 + `json` 子命令。
- `compile`、`screenshot` 两个别名已不可用（前者指向已移除的 `manage_workflow`，
  后者依赖未安装的 PIL），分别改用 `request_compile` 与原始调用。
- **不要在同步 C# 探针里推进协程**：`Time.unscaledDeltaTime` 为 0 会导致死循环锁死主线程。

### 7.2 编译门禁

菜单 `Gxdl/QA/写出编译报告`，或 Bridge 的 `request_compile`。
产出 `Logs/qa/compile-report.json`，含 error 列表与编译器状态。

### 7.3 自检运行器

菜单 `Gxdl/QA/运行自检`（也可用 Bridge 的 `execute_menu_item`）。
产出 `Logs/qa/selftest-report.json`，12 项核心契约：

- 服务容器未注册时报错清楚
- 事件订阅与退订生效
- 事件处理器异常不影响其它订阅者
- 流程切换先 Leave 后 Enter
- 流程 CanEnter 为假时拒绝切换
- 重复注册流程被拒绝
- 存档路径按作用域隔离
- 非法存档作用域被拒绝
- 技能默认表与现有规则一致
- 任务进度累计与完成判定
- 任务前置未完成时锁定
- 角色切换广播事件

### 7.3 启动游戏

项目自带文件触发入口，供无法调用 Unity API 的外部进程使用：

```
写入 Tools/run-game.trigger → 编辑器轮询捕获 → 自动进 Play Mode
结果写入 Logs/run-game.txt
```

菜单方式：`Gxdl > 运行游戏`（Ctrl+Shift+G）。
